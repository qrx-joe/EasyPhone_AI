# EasyPhone AI PRD

> 中文副名：爸妈别急  
> 版本：v1.0  
> 项目类型：AI Agent / AI Application / Elderly Digital Safety  
> 项目定位：给低识字中老年人的 AI 语音手机教练  
> 适用场景：UCWS Singapore Hackathon 2026 / AI Agent & Application Track

---

## 1. 项目概述

### 1.1 项目名称

**EasyPhone AI**

中文副名：**爸妈别急**

### 1.2 一句话定位

**EasyPhone AI 是一个给低识字中老年人的 AI 语音手机教练：普通手机问题一步一步教，遇到验证码、转账、陌生链接、屏幕共享等高风险场景时，先停下来，再找家人确认。**

英文一句话：

> EasyPhone AI is an AI voice phone coach for low-literacy seniors. It guides safe phone tasks step by step, and stops risky actions before scams happen.

### 1.3 项目核心价值

许多中老年人并不是不愿意使用智能手机，而是面对复杂页面、弹窗、验证码、陌生链接和支付流程时，会因为看不懂、说不清、不会搜索而感到紧张。

EasyPhone AI 的目标不是替老人操作手机，也不是替家人做决定，而是：

- 让老人可以直接用语音说出问题；
- 让 AI 把复杂手机操作拆成一步一步的简单指令；
- 让高风险操作在发生前被及时拦截；
- 让老人说不清的问题变成家人能看懂的求助单；
- 降低数字鸿沟和诈骗风险。

### 1.4 产品本质

EasyPhone AI 不是普通教程 App，也不是开放社区，而是一个具有安全边界的 AI 语音 Agent。

它负责四件事：

1. 听懂老人遇到的手机问题；
2. 判断问题属于低风险操作还是高风险场景；
3. 对低风险问题进行一步一步语音引导；
4. 对高风险问题立即停止指导，并生成家人求助单。

## 2. 背景与问题

### 2.1 背景

智能手机已经成为生活入口。微信沟通、视频通话、医保服务、生活缴费、短信验证、出行、购物、银行通知等都离不开手机。

但对低识字或不熟悉数字设备的中老年人来说，智能手机经常不是便利工具，而是一个高压系统。

他们常见的问题包括：

- 不会打字；
- 不会搜索教程；
- 看不懂弹窗；
- 分不清哪些按钮可以点；
- 遇到验证码、转账、陌生链接会慌；
- 遇到诈骗信息时缺少判断能力；
- 向子女求助时说不清页面和问题。

### 2.2 老人端痛点

#### 1. 不会准确表达问题

老人不会说“通知权限被关闭”或“自动续费扣款”，他们可能只会说：

- “微信没有声音了。”
- “它老是扣钱。”
- “手机字太小了。”
- “这个短信说医保卡不能用了。”

#### 2. 不会搜索和阅读教程

传统教程通常依赖文字、截图和专业术语，对低识字老人不友好。

#### 3. 害怕点错

许多老人不是不想学，而是不敢点。他们害怕：

- 把钱弄没；
- 手机坏掉；
- 删除重要内容；
- 点到诈骗链接；
- 泄露验证码或支付密码。

#### 4. 高风险场景容易被骗

验证码、银行卡、退款、客服、医保异常、中奖、远程控制、屏幕共享等场景，对老人来说极具迷惑性。

#### 5. 不想一直麻烦子女

老人可能反复遇到同类问题，但不好意思一直问子女。

### 2.3 子女端痛点

子女通常是家庭里的“远程技术支持者”，但他们也面临困难：

- 父母描述问题不清楚；
- 电话指导效率低；
- 同一个问题要反复教；
- 无法及时判断父母遇到的是普通问题还是诈骗风险；
- 担心父母误点链接、泄露验证码或被诱导转账。

## 3. 目标用户

### 3.1 核心用户：低识字中老年人

| 项目 | 描述 |
|---|---|
| 年龄 | 55 岁以上，重点是 60 岁以上 |
| 数字能力 | 会接打电话、微信语音、刷短视频，但不会复杂设置 |
| 识字能力 | 不识字、低识字，或不习惯阅读长文本 |
| 输入方式 | 更习惯语音，不习惯打字 |
| 常见问题 | 微信没声音、字体太小、手机卡、空间不足、弹窗看不懂、短信疑似诈骗 |
| 核心需求 | 有人慢慢说、一步一步教、危险时先提醒 |

### 3.2 次级用户：子女

| 项目 | 描述 |
|---|---|
| 年龄 | 25-45 岁 |
| 角色 | 远程帮助父母解决手机问题的人 |
| 核心需求 | 快速理解父母遇到的问题，降低重复沟通成本，减少诈骗风险 |
| 典型场景 | 父母发来“手机又不行了”，但说不清具体页面 |

### 3.3 潜在用户：社区服务者 / 老年大学 / 志愿者

这些人可以使用 EasyPhone AI 作为适老化手机教学工具，用于社区数字技能培训、反诈宣传和日常帮助。

## 4. 产品目标

### 4.1 用户目标

EasyPhone AI 希望帮助老人：

- 不打字也能提问；
- 不搜索也能获得指导；
- 一次只做一步，降低操作压力；
- 遇到风险内容时先停下来；
- 更容易向家人说明问题。

### 4.2 子女目标

EasyPhone AI 希望帮助子女：

- 快速看懂父母遇到的问题；
- 判断是否存在诈骗或资金风险；
- 减少远程沟通中的反复解释；
- 在高风险场景中及时介入。

### 4.3 黑客松 Demo 目标

在 2-3 分钟内展示完整闭环：

```text
老人语音提问
→ AI 理解问题
→ 判断风险等级
→ 低风险：一步一步语音引导
→ 高风险：停止操作并提醒
→ 生成家人求助单
```

### 4.4 非目标

第一版不做：

- 远程控制手机；
- 读取短信；
- 读取通讯录；
- 读取定位；
- 自动保存敏感截图；
- 指导转账；
- 指导输入验证码；
- 指导下载陌生 App；
- 开放社区广场；
- 陌生人私信；
- 医保、社保、金融代办。

## 5. 核心产品原则

### 5.1 语音优先

老人可以不打字、不搜索、不阅读长文，只通过“说话”和“听”完成主要流程。

### 5.2 每次只教一步

系统不输出长篇教程。每次只显示一个操作步骤，每句话尽量短、慢、明确。

原则：

- 一次只说一步；
- 每句话尽量不超过 20 个字；
- 不使用专业术语；
- 等用户确认“好了”再进入下一步；
- 用户说“没看到”时换一种说法；
- 用户说“点错了”时引导返回。

### 5.3 高风险先停下

遇到验证码、银行卡、转账、陌生链接、屏幕共享、远程控制、贷款、中奖、医保异常等内容时，系统必须停止操作指导。

### 5.4 不替老人做决定

AI 不做金融、医疗、法律判断，不直接告诉用户“可以转账”“可以输入验证码”。

AI 只做：

- 解释；
- 提醒；
- 分步引导；
- 生成求助单；
- 建议联系家人或官方渠道确认。

### 5.5 安全优先于完成任务

本产品的核心不是“尽快完成操作”，而是“安全地完成低风险操作，并在高风险场景中及时停下”。

## 6. MVP 范围

### 6.1 第一版必须完成

1. **语音提问**  
   老人按住按钮说出手机问题。

2. **问题理解与分类**  
   AI 判断问题属于手机设置、微信、空间清理、短信弹窗、安全风险等哪一类。

3. **风险等级判断**  
   根据关键词和语义判断低风险、中风险、高风险、极高风险。

4. **分步语音引导**  
   对低风险问题输出大字步骤和语音播报，每次只给一步。

5. **风险识别与中断**  
   对高风险问题不进入教程流程，而是进入安全提醒页。

6. **家人求助单生成**  
   把老人说不清的问题整理成子女能看懂的文字。

### 6.2 第一版暂不做

- 不做真实家人账号绑定；
- 不接入微信发送；
- 不读取短信和屏幕内容；
- 不做截图识别；
- 不做远程控制；
- 不做开放社区；
- 不做复杂后台。

## 7. 核心功能设计

## 7.1 功能一：语音提问

### 功能描述

老人打开首页后，点击或长按“按住说话”按钮，用自然语言描述问题。

示例：

- “微信没有声音了。”
- “手机字太小了。”
- “这个短信说我中奖了。”
- “它让我输入验证码，能不能输？”
- “有人让我开屏幕共享。”

### 用户流程

```text
点击“我想问”
→ 按住说话
→ 系统语音转文字
→ AI 理解问题
→ 进入问题确认页
```

### 页面要求

- 主按钮足够大；
- 文案简单；
- 支持语音提示；
- 支持重新说一遍；
- 支持直接找家人。

### 验收标准

- 用户能通过语音输入问题；
- 系统能展示识别文本；
- 用户可以确认或重新输入；
- 低风险问题进入教程流程；
- 高风险问题进入风险提醒流程。

---

## 7.2 功能二：问题确认

### 功能描述

AI 初步理解问题后，不直接进入教程，而是先向老人确认。

示例：

```text
你是不是想解决：微信没有声音？
```

按钮：

- 是的；
- 不是，重新说；
- 找家人。

### 设计目的

低识字老人表达可能模糊，AI 也可能误解。问题确认页可以减少错误指导。

### 验收标准

- 页面能展示 AI 理解的问题；
- 用户可以确认；
- 用户可以重新语音输入；
- 用户可以跳转到家人求助。

---

## 7.3 功能三：分步语音引导

### 功能描述

对于低风险问题，系统生成一组步骤，并逐步播报。

示例：微信没有声音。

第 1 步：

```text
先打开微信。打开以后，点“好了”。
```

用户点击或说“好了”后，进入第 2 步：

```text
点右下角的“我”。点完以后，说“好了”。
```

### 用户反馈处理

| 用户反馈 | 系统响应 |
|---|---|
| 好了 | 进入下一步 |
| 没看到 | 换一种说法 |
| 听不清 | 重复当前步骤 |
| 点错了 | 给出返回提示 |
| 不弄了 | 停止教程 |
| 找家人 | 生成求助单 |

### 页面元素

- 当前步骤编号；
- 大字步骤；
- 语音播放按钮；
- 好了；
- 没看到；
- 点错了；
- 找家人。

### 验收标准

- 每次只展示一个步骤；
- 支持语音播报；
- 用户点击“好了”后进入下一步；
- 用户点击“没看到”后出现替代表达；
- 用户可随时停止或找家人。

---

## 7.4 功能四：风险识别与中断

### 功能描述

当 AI 识别到高风险内容时，不继续提供操作教程，而是进入风险提醒页。

### 高风险关键词

包括但不限于：

- 验证码；
- 银行卡；
- 转账；
- 汇款；
- 中奖；
- 贷款；
- 退款；
- 客服；
- 远程控制；
- 屏幕共享；
- 下载 App；
- 医保异常；
- 社保异常；
- 身份证；
- 支付密码；
- 陌生链接；
- 二维码；
- 投资；
- 返利。

### 风险等级

| 风险等级 | 说明 | 处理方式 |
|---|---|---|
| 低风险 | 普通手机设置问题 | 正常分步引导 |
| 中风险 | 可能涉及权限、扣费、账号设置 | 先提示注意事项，再谨慎引导 |
| 高风险 | 涉及钱、验证码、链接、账户安全 | 停止教程，建议找家人确认 |
| 极高风险 | 涉及转账、屏幕共享、远程控制、支付密码 | 不提供任何操作步骤，只提醒停止 |

### 风险提醒文案

```text
先别急，这个可能有风险。
不要转账。
不要告诉别人验证码。
不要点陌生链接。
不要打开屏幕共享。
我可以帮你发给家人看看。
```

### 验收标准

- 系统能识别高风险关键词；
- 高风险内容不会进入普通教程；
- 页面明确提示“不转账、不说验证码、不点陌生链接”；
- 用户可以生成家人求助单。

---

## 7.5 功能五：家人求助单

### 功能描述

当老人说不清问题，或问题存在风险时，AI 自动生成一段子女能看懂的求助信息。

### 示例

老人原话：

```text
这个短信说医保卡不能用了，让我点进去。
```

系统生成：

```text
爸爸/妈妈收到一条疑似医保异常短信，短信中要求点击链接处理。
风险等级：高。
建议先不要点击链接，不要输入身份证号、银行卡号或验证码。
请你帮忙确认是否为官方医保渠道通知。
```

### MVP 实现方式

第一版不强制接入微信或短信 API，只提供：

- 复制求助内容；
- 生成分享卡片；
- 模拟发送给家人；
- 后续版本再考虑家人端账号体系。

### 验收标准

- 能根据老人问题生成简洁求助摘要；
- 能标记风险等级；
- 能给出子女可执行建议；
- 支持复制或保存分享。

---

## 7.6 功能六：常见问题教程库

### 功能描述

第一版内置少量高频场景，确保 Demo 稳定。

### 首批场景

| 场景 | 风险等级 | 说明 |
|---|---|---|
| 手机字体太小 | 低 | 典型适老需求 |
| 微信没有声音 | 低 | 高频沟通问题 |
| 手机空间不足 | 中 | 可能涉及删除数据 |
| 手机充不进电 | 低 | 可给基础排查步骤 |
| 关闭自动续费 | 中高 | 涉及扣费，需谨慎 |
| 收到中奖短信 | 高 | 防诈骗场景 |
| 对方要验证码 | 高 | 典型风险场景 |
| 要求开屏幕共享 | 极高 | 明确高危场景 |

### 设计要求

- 白名单场景优先；
- 每个教程人工预设基础步骤；
- AI 只负责适老化改写和语音化表达；
- 高风险场景只给风险提醒，不给继续操作步骤。

## 10. AI Agent 设计

### 10.1 AI 输入

AI 输入包括：

- 用户语音转写文本；
- 当前选择的问题类型；
- 是否来自高风险场景；
- 用户反馈，如“好了 / 没看到 / 点错了”。

### 10.2 AI 输出

AI 输出包括：

- 问题分类；
- 风险等级；
- 简短问题确认句；
- 分步教程；
- 替代表达；
- 风险提醒；
- 家人求助单。

### 10.3 Agent 决策流程

```text
用户语音输入
→ ASR 转写
→ AI 分类问题
→ 风险词库初筛
→ LLM 语义判断
→ 输出风险等级
→ 低风险：进入分步指导
→ 中风险：先提醒再谨慎指导
→ 高风险：停止指导并生成求助单
→ 极高风险：只提醒停止并联系家人
```

### 10.4 Prompt 规则

核心系统提示词：

```text
你是一个面向不识字 / 低识字中老年人的手机使用助手。
你必须使用短句、慢节奏、低术语表达。
每次只给一步操作。
遇到验证码、转账、银行卡、陌生链接、屏幕共享、远程控制、医保、社保、贷款、中奖等内容时，必须立即停止操作指导，只给出风险提醒，并建议联系家人或官方渠道确认。
你不能指导用户转账、输入验证码、下载陌生 App、打开屏幕共享或提供支付密码。
```

### 10.5 输出格式建议

```json
{
  "category": "wechat_notification",
  "risk_level": "low",
  "confirmed_question": "你是不是想解决：微信没有声音？",
  "steps": [
    {
      "step_index": 1,
      "step_text": "先打开微信。打开以后，点“好了”。",
      "fallback_text": "微信是绿色图标，里面有两个白色小气泡。"
    }
  ],
  "family_message": ""
}
```

## 11. 隐私与安全设计

### 11.1 隐私原则

第一版必须遵守最小化原则：

- 不默认要求手机号注册；
- 不读取通讯录；
- 不读取短信；
- 不申请定位；
- 不自动保存原始语音；
- 不保存敏感截图；
- 不开放陌生人私信；
- 不展示二维码、手机号、微信号、外链；
- 高风险内容不进入公开社区；
- 明确提示用户不要说验证码、银行卡号、身份证号。

### 11.2 敏感信息提醒

语音输入前提示：

```text
请不要说验证码、银行卡号、身份证号、支付密码。
```

截图上传前提示，后续版本：

```text
请遮住手机号、身份证号、银行卡号、验证码和住址。
```

### 11.3 高风险处理原则

一旦识别到高风险内容：

1. 停止教程；
2. 播报风险提醒；
3. 生成家人求助单；
4. 不保存原始敏感内容；
5. 不进入社区或公开回答池。

## 15. 核心风险与应对

### 风险 1：真实老人不会主动打开产品

判断：高风险。

应对：第一版定位为“子女帮父母打开后使用”，后续再考虑桌面快捷入口、微信小程序、手机厂商合作。

### 风险 2：语音识别听不懂方言

判断：中高风险。

应对：MVP 先支持普通话；路演时说明后续可接入方言 ASR。

### 风险 3：AI 乱教操作

判断：高风险。

应对：第一版采用白名单教程库，高风险场景不生成操作步骤。

### 风险 4：隐私合规压力

判断：高风险。

应对：不读取短信、通讯录、定位；不保存敏感内容；截图和语音仅用于本次分析。

### 风险 5：社区变成诈骗入口

判断：极高风险。

应对：第一版不开放老人端社区，社区能力仅作为后台审核与教程沉淀机制。

### 18.2 项目差异化

EasyPhone AI 的核心差异不是“AI 会回答手机问题”，而是：

> AI 知道什么时候应该一步一步教，也知道什么时候必须停下来。

这让它区别于普通聊天机器人、教程 App 和反诈宣传页面。

EasyPhone AI is built for seniors who cannot type, search, or understand complex phone pop-ups.

EasyPhone AI 是给低识字中老年人的 AI 语音手机教练。

## 19. 最终判断

EasyPhone AI 是一个适合黑客松的项目，因为它同时满足四个条件：

1. 痛点真实具体；
2. AI 作用明确；
3. Demo 易于展示；
4. 社会价值和安全边界都清楚。

第一版不应该做成“大而全的老人手机助手”，也不应该做成开放社区。最理性的版本是：

> **给低识字中老年人的 AI 语音手机教练：普通问题一步一步教，危险问题先停下来。**

项目最终主线：

```text
EasyPhone AI does not just help seniors use smartphones.
It helps them use smartphones safely.
```

中文：

```text
EasyPhone AI 不只是帮助老人使用手机，
而是帮助他们更安全地使用手机。
```
