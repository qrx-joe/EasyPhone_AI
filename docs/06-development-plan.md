# 项目开发计划

> 项目：EasyPhone AI / 爸妈别急
> 版本：MVP 开发计划 v1
> 日期：2026-06-04
> 核心目标：先做出可演示、可验证、不会越界的 AI 语音手机教练 MVP。

## 1. 当前阶段判断

项目目前处在“PRD 已明确，开发尚未开始”的阶段。

当前最重要的事不是继续扩写需求，而是尽快进入可运行原型：

```text
首页
-> 输入问题
-> AI/规则判断风险
-> 低风险一步一步教
-> 高风险停下来
-> 生成家人求助卡
```

第一版只服务这个闭环。任何不能强化这个闭环的功能，都先放进 `01-to-do.md`，不要进入本轮开发。

## 2. MVP 成功标准

- 本地项目可以启动。
- 手机竖屏页面可正常浏览。
- 三个 Demo 场景可以跑通：微信没有声音、手机字体太小、医保异常短信加验证码。
- 高风险输入不会进入普通教程。
- 每次只展示一个步骤。
- 家人求助卡清楚、可复制。
- 没有读取短信、通讯录、定位、真实支付、远程控制等越界能力。

## 3. 推荐技术方案

### 3.1 第一版技术栈

- 前端：Next.js + React + TypeScript。
- 样式：Tailwind CSS。
- 语音识别：浏览器 Web Speech API。
- 语音播报：浏览器 SpeechSynthesis。
- 风险判断：本地关键词规则优先。
- AI：第一阶段可先模拟，第二阶段再接 API。
- 数据：本地 JSON + localStorage。
- 部署：Vercel 或 Cloudflare Pages。

### 3.2 接入 AI 的顺序

不要一上来接 AI API。那样很容易把项目做成“模型调参游戏”，而不是产品。

建议顺序：

1. 先做规则版可运行 MVP。
2. 再接 AI 分类和求助卡生成。
3. 最后做语音体验优化。

风险判断必须有规则兜底，AI 只是增强，不是安全核心。

## 4. 开发里程碑

## Milestone 0：项目初始化

目标：建立可运行项目骨架。

任务：

- 初始化 Next.js + TypeScript 项目。
- 配置 Tailwind CSS。
- 建立基础目录：
  - `src/app`
  - `src/components`
  - `src/domain/risk`
  - `src/domain/tutorial`
  - `src/domain/agent`
  - `src/lib/speech`
- 建立基础页面路由。

验收：

- 本地开发服务器可启动。
- 首页能正常显示。
- TypeScript 无明显报错。

## Milestone 1：核心领域模型

目标：先把“风险判断”和“教程数据”从 UI 里分离出来。

任务：

- 定义 `RiskLevel`。
- 定义 `QuestionRecord`。
- 定义 `TutorialStep`。
- 定义 `HelpRequest`。
- 建立风险关键词库。
- 实现 `classifyRiskByRules()`。
- 实现 `shouldStopGuidance()`。
- 建立首批教程库。

验收：

- 输入“验证码”时返回高风险。
- 输入“屏幕共享”时返回极高风险。
- 输入“微信没有声音”时返回低风险。
- UI 不直接写死风险判断逻辑。

## Milestone 2：首页与输入流程

目标：用户能从首页提出问题，并进入确认页。

任务：

- 首页大按钮。
- 文本输入兜底。
- 语音输入按钮。
- 敏感信息提醒。
- 问题确认页。

验收：

- 用户可以输入“微信没有声音了”。
- 页面显示“你是不是想解决：微信没有声音？”。
- 用户可以确认或重新输入。

## Milestone 3：低风险分步指导

目标：跑通低风险教程。

任务：

- 根据问题匹配教程。
- 展示当前步骤。
- 实现“好了”进入下一步。
- 实现“没看到”显示替代表达。
- 实现“点错了”安全返回提示。
- 实现语音播报当前步骤。

验收：

- “微信没有声音”可以展示至少 3 步。
- “手机字体太小”可以展示至少 3 步。
- 每次只显示一个步骤。
- 点击“好了”才进入下一步。

## Milestone 4：高风险中断

目标：高风险场景必须停下来。

任务：

- 建立风险提醒页。
- 高风险输入跳转到风险提醒。
- 生成家人求助卡。
- 支持复制求助卡。
- 支持模拟发送。

验收：

- 输入“短信让我输验证码”不会展示教程步骤。
- 输入“对方让我开屏幕共享”不会展示教程步骤。
- 页面明确提示不要转账、不要说验证码、不要点陌生链接、不要开屏幕共享。
- 家人求助卡能说明问题和建议动作。

## Milestone 5：AI 接入

目标：在规则兜底基础上接入 AI，提高问题理解和求助卡质量。

任务：

- 建立 Agent 输出 JSON schema。
- 写系统 Prompt。
- 接入 AI API。
- 增加异常兜底：AI 失败时仍使用规则与本地模板。
- 对 AI 输出做校验。

验收：

- AI 输出必须符合结构化 JSON。
- AI 判断高风险或规则判断高风险，任一命中都停止指导。
- AI 不能输出危险操作步骤。
- API 失败时 Demo 仍能跑通。

## Milestone 6：Demo 打磨与部署

目标：形成 2-3 分钟可展示版本。

任务：

- 优化移动端布局。
- 调整文案。
- 准备三个 Demo 快捷入口。
- 写路演脚本。
- 部署线上 Demo。
- 截图和录屏。

验收：

- 手机竖屏无文字遮挡。
- 三个场景可以稳定复现。
- 路演 2-3 分钟内讲完闭环。
- 风险中断是 Demo 的记忆点。

## 7. 测试计划

### 7.1 风险判断测试

必须覆盖：

- “微信没有声音了” -> low。
- “手机字太小” -> low。
- “手机空间不够” -> medium。
- “短信让我输入验证码” -> high。
- “对方让我开屏幕共享” -> critical。
- “让我转账才能退款” -> critical。
- “点这个陌生链接领奖” -> high。

### 7.2 UI 测试

- 手机竖屏。
- 桌面宽屏。
- 长文案是否溢出。
- 按钮是否足够大。
- 风险提醒是否足够醒目。

### 7.3 安全测试

- 高风险输入不能出现教程步骤。
- AI 输出不能覆盖规则兜底。
- 求助卡不展示验证码、银行卡号、身份证号、支付密码。

## 8. 架构坏味道预警

### 1. 把风险判断写在页面组件里

这是僵化和脆弱性的开始。风险判断必须放在 `domain/risk`。

### 2. 教程步骤到处复制

这是冗余。教程必须集中在教程库里。

### 3. 一开始就引入复杂后台

这是不必要复杂性。MVP 先用本地数据。

### 4. 完全相信 AI

这是安全事故预备役。规则兜底必须优先。

### 5. 页面塞太多说明文字

这是适老化失败。老人端每个页面只做一个动作。
