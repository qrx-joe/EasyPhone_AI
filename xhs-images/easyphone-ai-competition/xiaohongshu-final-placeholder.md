## 正文

我把这次参赛项目收敛到一个很具体的场景：海外华人长者收到英文银行短信、WhatsApp 消息、验证码请求或屏幕共享邀请时，先别急着点，先判断这件事能不能继续。

很多时候，爸妈问的不是一个完整技术问题，而是一句很短的话：“这个能不能点？”“微信怎么没声音？”“这个验证码要不要发？”  
手机系统、银行通知和政府服务常常是英文，家庭沟通却以中文为主。子女不在身边时，一次求助要来回描述很多遍，风险也容易在这个过程中被忽略。

所以我做了 EasyPhone AI。

它不是替爸妈直接操作手机，而是先判断风险，再决定是否继续指导。

普通问题会进入大字、短句、一次只给一步的教程。比如“微信没有声音了”，它会先确认问题，再把解决步骤拆开讲。

但如果涉及 OTP、验证码、转账、陌生链接、屏幕共享或远程控制，它会停止操作指导，提醒联系家人或官方渠道，并生成一张家人求助卡。

参赛版把 Google Gemini 放在两个设计位置：

1. 对本地规则判断为低风险的输入做语义复检，用来发现关键词可能漏掉的风险表达；
2. 把长者的模糊描述整理成家人更容易读懂的求助说明。

安全边界是我这次最看重的部分：本地规则始终优先，Gemini 只能升级风险，不能降低本地规则已经给出的风险等级；模型超时、HTTP 错误、JSON 异常或业务校验失败时，产品会回到固定规则和模板。

当前原型已经完成：

- 文字/语音输入；
- 普通问题分步教程；
- 高风险问题拦截；
- 家人求助卡；
- Gemini API 接入代码、结构化输出和降级逻辑；
- 公开 GitHub 分支和在线 Demo。

目前还没有可用的 Gemini API Key，所以真实 Gemini 成功输出先作为占位项保留。我已经在 AI Studio 里做过一次真实审查尝试，但当前项目提示需要设置结算信息，暂时不能把它写成“Gemini 已成功给出建议”。这一点我会在后续拿到可用 Key 后补齐。

当前测试结果：共 211 项，210 项通过，0 项失败，1 项 WCAG AAA 颜色目标跳过；生产构建通过。

我想先把“文字安全链路”跑稳：什么时候教、什么时候停、什么时候找家人。截图多模态和更完整的新加坡本地化验证会放在下一阶段继续做。
