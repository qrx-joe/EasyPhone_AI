## 正文

这次参赛，我没有做一个“什么都能聊”的助手。

我只盯着一个很小、但我觉得很真实的场景：海外华人长者遇到手机问题时，第一反应往往不是描述完整故障，而是问一句：

“这个能不能点？”

“这个验证码要不要发？”

“微信怎么突然没声音了？”

麻烦就在这里。银行短信、政府服务、WhatsApp 提醒经常是英文；家里沟通又大多是中文。爸妈不一定分得清“普通设置问题”和“诈骗风险”，子女也不一定随时在旁边。

所以我做了 EasyPhone AI。

它不是替爸妈操作手机，也不是一上来就回答。它先判断：这件事能不能继续。

如果只是普通问题，比如“微信没有声音了”，它会用大字、短句、一次一步的方式慢慢教。

但只要碰到转账、OTP、验证码、陌生链接、屏幕共享、远程控制这类词，它就不继续教操作了。先停下。然后提醒找家人或官方渠道确认，再生成一张家人求助卡。

我挺喜欢这个设计点：AI 不一定要显得很聪明，有时候它最有价值的动作就是“不往下说”。

参赛版里，我把 Google Gemini 放在两个位置：

第一，用来复检那些本地关键词可能漏掉的中英混合风险表达。  
第二，把长者说得有点乱的问题，整理成家人能快速看懂的求助说明。

但这里我没有把决定权全交给模型。

本地规则永远优先。Gemini 只能把风险往上提，不能把已经命中的高风险降下来。只要模型超时、返回格式不对、接口报错，系统就退回固定规则和模板。

目前原型已经跑起来了：

- 可以输入文字，也支持语音入口；
- 普通问题会进入分步教程；
- 高风险问题会被拦截；
- 可以生成家人求助卡；
- Gemini API 的接入代码、结构化输出和降级逻辑已经完成；
- GitHub 分支和在线 Demo 都已经公开。

也说清楚一个限制：我现在没有可用的 Gemini API Key，所以“真实 Gemini 成功输出”先占位。AI Studio 里我试过提交审查 prompt，但当前项目提示需要设置结算信息，暂时不能把它写成“Gemini 已经给出建议并被采纳”。

这点我宁愿写得笨一点，也不想把证据写虚。

当前测试结果是：共 211 项，210 项通过，0 项失败，1 项 WCAG AAA 颜色目标跳过；生产构建通过。

下一步我会先补 Gemini 的真实烟雾测试，再考虑截图多模态。先把“什么时候教、什么时候停、什么时候找家人”这条安全链路跑稳，比堆功能更重要。
